## 老師要的三件事

1. **時間**：技術概念何時出現、何時熱、現在還活著嗎？
2. **關聯與單位**：兩個概念關聯多強？是「幾篇專利」還是「**幾家機構**」在做？
   （老師原話舉的例子是「某公司和某學校都在做這個技術概念」——
   這句的分析單位是「家」，v1.2 全部以「篇」計算，回答不了。）
3. **先後**：哪個概念是另一個的前身？證據是什麼、可信度多高？

外加工程需求：**PNG 匯出**，讓多張圖能並排放進論文比對。

## 已定案的設計決策（連理由一起記，免得重犯）

**1. 距離不賦予語意。** `layout_distance_interpretation` 維持 v1.2 的
`'visual_only'`。曾設計 `springLength = L × (1 − 正規化關聯度)`，實測**結果相反**：
剛好通過 `support ≥ 2` 的孤立低頻對被畫成全圖最緊（springLength 0），
80 篇支持的高頻對被畫在最遠（246.8）。且 `springLength = 0`／負值在 vis-network
不拋錯，只會讓彈簧與 `avoidOverlap` 互鬥、抖動不收斂。
未來要做的正確路徑是 **VOS mapping／classical MDS ＋ Kruskal stress-1 失真指標**
（Waltman, van Eck & Noyons, arXiv:1006.1032 式 (3) 就是 VOS mapping，
該文明言與 MDS 密切相關），那才有可辯護的距離語意、且可跨圖比較。

**2. association strength 用於排序與引用，不用於線寬。**
正確公式（已回查一手來源，arXiv:1006.1032 式 (1)(2)，2026-08-05 核對）：

```
s_ij = 2m·c_ij / (c_i·c_j)     c_i = Σ_{j≠i} c_ij     m = ½·Σ_i c_i
```

`c_i` 是**總連結強度**（不是 document frequency），且**有 `2m` 因子`**。
草稿曾寫成 `c_ij/(w_i·w_j)` 並標為「VOSviewer 預設」——那實際上是 lift/N，
照那樣實作會讓老師引 Van Eck & Waltman (2009) 變成錯誤引用。

但實跑 fixture 顯示它**不適合當線寬**：因 `c_i` 排除自身，單邊網路
`s ≡ 2`（與 `c_ij` 無關）；k-clique 一般式為 `k/(k−1)`，所以稀疏概念網路上
`s` 幾乎恆 > 1，「門檻在 1」失效；且孤立低頻對可得 `s = 82` 而 80 篇支持的
高頻對得 `2.05` —— 與第 1 點移除距離映射的**同一個反轉機制**。
它本來是為「輸入給 VOS mapping／clustering 前的正規化」設計的，不是線寬純量。
又因 `m`（全網總連結數）在分子，**跨圖不可比較**。

決定：**線寬用有界指標**（`jaccard` 或 NPMI）；association strength 照正確公式
算、顯示於邊詳情、用於同一張圖內的排序與門檻，方法圖例明載其膨脹與
跨圖不可比的限制。

**3. 時序以統計為主力、引用為補強。** 實測可用內部引用只有 93 對／1869 筆。
引用投影到概念層時**必須排除兩篇共有的概念**（否則笛卡兒積會產生自環與二元環），
並做申請日一致性檢查與 DAG 環偵測。

**4. 統計時序不用統計檢定。** 曾寫「或 Mann–Whitney U 顯著」——在預設支持門檻
`k=3` 下 n₁=n₂=3、排列數 C(6,3)=20、最小雙尾 p = 0.10，**α=0.05 永不顯著**，
是死碼；且申請年為整數、重複值多，需 ties 校正。改用確定性條件
（分布不重疊 + 中位年份差 ≥ 1 + 支持數門檻），可完整重現、可人工核對。

**5. 百分位與中位數的插值方法必須明訂。** 實測同一組資料，nearest-rank 與
linear（Excel `PERCENTILE`／numpy 預設）在 `k=3` 時給**相反答案**；
`median_year` 取 lower／upper／平均也會決定箭頭有無。定案：nearest-rank +
lower median，並寫入 methodology。

**6. 同義詞合併只能在輸入層。** 事後合併會**靜默丟邊**：共現邊 id 是
概念 label 的 hash，合併後 `(AI, X)` 與 `(人工智慧, X)` 產生同一個 edge id，
而 `addEdge` 是 `if (!edgeSet.has(id))` → 第二條被丟棄，`support_count`
只留先到者而非聯集。這正是同義詞治理要修的問題。

**7. 兩種分析單位的社群必須分開持久化。** 現況 `concepts.community_id` 單值、
`communities` 主鍵無單位維度；而社群 id 直接沿用 graphology 回傳的整數、
顏色按 index 取色盤 → 兩種單位會產生**同一組 id 與同一組顏色但成員不同**。
後果：兩張 PNG 圖例都寫「社群 0：區塊鏈」、顏色相同、成員不同，
跨圖比對得到錯誤結論。

**8. 分析主單位＝機構（家），「篇」退為下鑽細節。**（2026-08-07 P4 定案，
與老師確認）老師要的「誰在做」與「某銀行＋某大學共同投入哪些技術」，分析
單位是**機構**。因此：機構節點圖（一圓＝一家機構，兩家共同投入 ≥k 個概念
連邊）升為 P4 主視圖；概念圖退為「技術地圖」輔視；機構類型（銀行/保險/大學/
其他…）需要新做一層「機構分類」（比照 P1 同義詞：跨分析共享、可人工編輯、
帶不可變快照）。**系統資料-agnostic**——現用樣本（56 家／1 大學）只供開發，
真實資料由老師端整理提供；樣本的厚薄、產業貼合度皆非本系統要處理的問題，
系統不得因樣本稀薄而當掉或偏差。
