# 論文方法章節撰寫指引：如何在學術論文中交代這套知識圖譜的設定

- **文件用途**：把 `知識圖譜分析結果解讀與概念抽取方法.md`（v2.4）的系統設定，轉成論文可直接使用的方法敘述、參數附錄與限制陳述。
- **核對日期**：2026-08-18（所有公式與參數均回查程式碼，見第五節對照表）
- **適用**：中文學位論文／期刊投稿；若投英文期刊，第三節段落可直譯，第五節表格照搬。

## 一、節點大小公式：務必採用的版本

來源文件 v2.3 的說明句、示例表與 §12.4 曾殘留舊值（斜率 6、上限 52），**已於 v2.4（2026-08-18）修正**。論文請一律採用與程式一致的版本：

```text
concept_size = min(72, max(10, 10 + 10 × √frequency))     # lib/concept-network.ts:44
```

對應示例：f=1→20、f=4→30、f=9→40、f=39→72（達上限）。若手上仍有 v2.3 或更早的文件副本、投影片或已寫入論文的段落，請逐處核對此公式與示例值。

其餘公式（申請人、機構、線寬、透明度、Louvain 參數、力導向參數、NPMI 規則）皆與程式一致，可直接引用；集中對照表見來源文件第十三節或本檔第五節。

## 二、先決定「這是什麼」：研究設計層級的定位

審稿人第一個問題不會是公式，而是「你憑什麼叫它知識圖譜」。建議在方法章開頭用兩句話把定位講死：

> 本研究建構之圖譜為**大型語言模型輔助建構之專利異質屬性知識圖譜（LLM-assisted heterogeneous attributed patent knowledge graph）**，包含三類具型別實體（申請人、專利、技術概念）與具名關係（申請了、包含、候選語意關係），並保存年份、頻率、支持數與來源專利等屬性，可由任一關係回溯至原始專利。由於技術概念與語意關係由模型抽取，尚未經領域本體對齊與專家逐筆校驗，本研究將其定位為**研究探索型／候選知識圖譜（exploratory candidate knowledge graph）**，而非已驗證之權威知識庫。

接著把三張圖對應到三個分析層級，明確說明「為什麼不是一張圖」——這是方法設計的貢獻點，不要當成 UI 功能寫：

| 系統視圖 | 論文中的名稱建議 | 圖論性質 | 回答的研究問題 |
| --- | --- | --- | --- |
| 專利脈絡圖 | 專利—申請人—概念**異質圖**（來源層） | 三層有向二部／三部圖，邊為資料存在關係 | 概念從哪來、由誰提出、何時提出（來源追溯與效度稽核） |
| 技術概念網路 | 技術概念**共現網路**（分析層） | 由專利—概念隸屬關係**投影**出的一模無向加權網路 | 哪些技術概念常同篇出現、形成哪些技術群聚 |
| 機構網路 | 機構—技術**連帶網路**（機構層） | 由機構—概念隸屬關係投影出的一模無向加權網路 | 哪些機構投入相同技術領域 |

**關鍵措辭**：概念網路與機構網路都要寫成「**投影（projection）**」而非「抽取」——它們不是另一次 LLM 呼叫的產物，而是同一份隸屬關係的二部圖投影。這句話同時解釋了為什麼三張圖的統計不會互相矛盾。

## 三、方法章節建議結構與可直接使用的段落

建議切成七個小節。以下每節先說「要寫什麼」，再給可直接貼上、只需替換數字的段落。

### 3.1 資料來源與抽樣

要寫：資料庫來源、檢索式與檢索關鍵字、檢索日期、年份範圍、原始筆數、實際分析筆數、**抽樣方式**。

> 本研究以〔資料來源〕之專利檢索結果為分析母體，檢索關鍵字為〔…〕，檢索日期為〔YYYY-MM-DD〕，共取得〔N₀〕筆。系統以匯入順序取前〔N〕筆進行分析，因此**本研究之樣本為依原始排序取前 N 筆之非隨機樣本**，非機率抽樣；原始排序若與相關度、年份或申請人有系統性關聯，將構成樣本偏誤，於研究限制中討論。分析單位為單一專利文件；每筆納入之欄位為專利名稱、專利摘要與申請人。申請日與申請號用於時間元資料與去重，不直接參與概念抽取。

（若可行，最強的補強是改成隨機抽樣或全樣本，並在論文中說明；若無法改，務必如上明寫，不要用「抽取樣本」含糊帶過。）

### 3.2 概念抽取程序（LLM 部分）

要寫：模型提供商、**確切 model ID**、prompt 版本、輸出格式、每篇概念數上限、排除規則、重試策略、失敗處理。這一節決定研究可重現性，寫得越具體越好。

> 技術概念以大型語言模型自專利摘要抽取。模型為〔提供商〕之〔model ID〕，提示詞版本為 `fintech-concepts-v2`，分析執行時間為〔YYYY-MM-DD〕。提示詞要求模型：(1) 將摘要整理為繁體中文；(2) 每篇抽取 5 至 10 個金融科技相關之具體概念；(3) 排除「系統」「方法」「裝置」等空泛詞；(4) 通用技術詞須帶金融應用場景；(5) 優先採用 2 至 6 字之業界標準詞彙；(6) 語意關係之兩端必須來自同篇之概念清單；(7) 每筆關係須回傳關係名稱、1–5 之權重、判讀理由，以及 `EXTRACTED`／`INFERRED`／`AMBIGUOUS` 之信心分類。專利以批次送入模型；單一批次回應若無法解析為正確筆數之 JSON 陣列，最多重試三次，全部失敗時該批專利仍保留於圖譜中，惟概念與關係為空，不以推測值填補。系統記錄 prompt 版本、模型提供商與 model ID，以交代生成條件。

### 3.3 概念正規化與圖譜建構

要寫：合併規則（這是概念邊界，審稿必問）、二部圖如何建立、投影如何計算。

> 模型回傳之概念清單經以下程式化清理：去除前後空白、移除空字串、以完全相同字串於篇內去重，並以穩定順序建立概念節點與概念配對。概念合併發生於共現計算之輸入層：完全相同之字串必然合併；納入同義詞表之異名（如「人工智慧」與「AI」）先正規化為同一代表詞後再合併。**未納入同義詞表之近似詞（如「行動支付」與「行動支付技術」）維持為兩個獨立節點**，此為本研究概念邊界之已知限制。模型產出之語意關係若其端點不在同篇之概念清單內，程式一律捨棄，以避免憑空新增節點。

### 3.4 網路指標

要寫：頻率、支持數、Jaccard、NPMI、association strength 各自的定義、單位（篇／家）與用途分工。定義寫成公式，並明確說明**哪個指標用於什麼**——同一份資料算了四個指標卻不說用途，是常見扣分點。

> 令 `P(A)` 為包含概念 A 之相異專利集合，`N` 為分析樣本之專利總數。
>
> - 概念頻率：`f(A) = |P(A)|`，即涵蓋該概念之**相異專利篇數**（非摘要內詞頻、非引用數）。
> - 共現支持數：`support(A,B) = |P(A) ∩ P(B)|`，以相異專利 ID 去重後計算。
> - Jaccard 相似度：`J(A,B) = |P(A) ∩ P(B)| / |P(A) ∪ P(B)|`，值域 [0,1]，用於**線寬映射**與配對比較。
> - 正規化點間互資訊：以 `p_xy = support(A,B)/N`、`p_x = f(A)/N`、`p_y = f(B)/N` 計算 `NPMI = (ln p_xy − ln p_x − ln p_y)/(−ln p_xy)`，結果截斷於 [−1,1]。當 `p_xy = 1`（兩概念永遠共同出現）時 PMI 為 0、NPMI 之極限路徑相依，系統將其記為未定義，不參與線寬與排序。
> - Association strength：`a(A,B) = 2m·c_ij/(c_a·c_b)`（`c_i` 為概念 i 全部共現支持數之和，`m = ½Σc_i`），**僅用於圖內排序與門檻篩選，不映射為線寬**，以避免視覺上被誤讀為未經驗證之關係強度分數。
>
> 上述指標同時提供「篇」與「家」兩種分析單位：前者以相異專利為計數基礎，後者以相異申請機構為計數基礎，兩單位之指標各自獨立計算與儲存。

若要引用方法文獻：Jaccard 與 association strength 的正規化性質見 van Eck & Waltman (2009)；NPMI 見 Bouma (2009)；共詞分析傳統見 Callon et al. (1983)。（引用格式請回查原文。）

### 3.5 社群偵測

要寫：演算法、實作套件、參數、邊權重、隨機性處理、孤立節點處理、社群命名規則。

> 技術群聚以 Louvain 模組度最佳化演算法辨識（Blondel et al., 2008），實作採 `graphology-communities-louvain`，參數為 `resolution = 1`、`randomWalk = false`（即不使用隨機游走近似，以確保同一輸入產生可重現之分區）。**社群偵測僅使用概念共現邊，邊權重為 `support_count`；模型判讀之語意關係不參與計算。**「篇」與「家」兩分析單位各自獨立分區。無任何共現邊之概念各自形成單點社群。社群名稱取該社群內度數最高之概念，僅為標籤，不代表該社群之定義或上位概念。

務必補一句解釋權界線：

> Louvain 之分區為資料驅動之結構分群，表示在本樣本與建圖規則下「內部共現較為緊密」之概念集合，既不表示群內概念互為同義，亦非唯一正確之技術分類。

### 3.6 視覺映射（大小、線寬、透明度、顏色、方向、位置）

要寫：每個視覺通道對應哪個量、公式與參數值。學位論文常整節省略，但這節是「圖能不能被引用」的關鍵——讀者看圖時只能靠視覺通道，映射不交代，圖就不是證據。

> 節點大小：概念節點 `min(72, max(10, 10 + 10·√f))`；申請人節點 `min(52, max(18, 18 + 5·√n_patents))`；機構節點 `min(52, 18 + 5·√n_concepts)`；專利節點固定為 18，**故專利節點之大小不表示價值、品質或引用數**。平方根縮放用於抑制高頻概念之面積過度放大，`min/max` 為顯示尺寸之上下界。
>
> 邊寬：共現邊採有界指標映射，預設 `width = min(8, 1 + 7·J)`，切換為 NPMI 時 `width = min(8, 1 + 7·max(0, NPMI))`；機構共享概念邊 `width = min(8, 1 + 1.4·√support)`；語意關係邊與引用佐證邊固定 1.5，**不隨模型權重變化**。共現邊之透明度依支持數遞增：`opacity = 0.30 + 0.70·(1 − e^(−support/5))`，其中 τ = 5 為視覺啟發參數，非信心水準。
>
> 顏色：概念節點顏色代表 Louvain 社群；機構節點顏色代表依機構名稱關鍵字規則判定之機構類型（銀行、金控、保險、大學、證券投承、支付金流、科技、學研、個人、其他），為粗略之產業標籤，非官方產業分類，可能誤判。
>
> 節點位置：座標由 vis-network 之 `forceAtlas2Based` 力導向求解器收斂產生，斥力 `F_r = k(deg_i+1)(deg_j+1)/d²`、彈簧引力 `F_s = c(d − L)`、向心力 `F_c = γd`，參數為 k = −150（節點數 ≥120 之大圖為 −80）、L = 250（大圖 150）、c = 0.04、γ = 0.003、damping = 0.5、avoidOverlap = 1、maxVelocity = 50、minVelocity = 0.75、穩定化迭代 200（大圖 130、超大圖 80）。語意關係邊與機構邊不參與力學模擬（`physics: false`）。

然後放這句**限制聲明**——建議同時出現在方法章與每張圖的圖說：

> 力導向座標僅供視覺排版之用；圖中任意兩節點之畫面距離**不構成定量研究指標**，不得解讀為語意相似度、共現機率、因果強度、競爭程度、統計顯著性或時間先後。概念間之比較應依共現支持數、Jaccard／NPMI 與來源專利進行。

### 3.7 方向性與階層（若論文有用到時間視圖／IPC）

這是最容易被過度解讀的一節。三種方向要分開寫，用詞不能混：

> **語意關係方向**由模型抽取時判定，`source → target` 即箭頭方向，系統不改寫；聚合多篇相同三元組時，邊權重為各篇模型權重之平均值（權重值域 1–5）。此類關係為**候選關係**，須回查來源專利與判讀理由。
>
> **時間方向**依兩端概念之涵蓋專利申請年**中位數**排序決定：`median(A) < median(B)` 則 A → B，反之則 B → A，相等或任一端缺值則不設方向。中位數隨當前選取之 IPC、來源檔與年份範圍以同一批專利重新計算。產生時間箭頭之必要條件為：(1) 兩概念已由共同專利形成共現關係；(2) 兩端在當前分析子集內均有可比較且不相等之中位申請年。此箭頭僅表示「在本樣本中何者較早出現」，**不應稱為先輩／祖先關係，亦不代表技術演進、依賴或因果**；主張技術傳承須另以引用鏈、權利項內容與領域專家判讀驗證。
>
> **引用佐證**不改變方向，僅作一致性分類：以順向引用數 f、反向引用數 r 計算 `net = max−min`、`ratio = max/min`，於 `net ≥ 2` 且 `ratio ≥ 2` 時判定成立；`f > r` 標示為與時間排序一致（aligned），`f < r` 標示為衝突（conflicting）。
>
> **階層關係**僅存在於 IPC 分類樹：正規化 IPC 依代碼前綴投影為五級（`G` / `G06` / `G06Q` / `G06Q10` / `G06Q10/10`），前一級為後一級之父層，用於瀏覽、篩選與著色，**不產生概念網路上之任何箭頭**。概念網路無樹狀階層排版，圖中之垂直位置不代表上下位。

**用詞紅線**（建議在寫作時當 checklist 逐句掃）：

| 不可寫 | 應寫 |
| --- | --- |
| 節點越大越重要／影響力越高 | 節點越大表示涵蓋之相異專利（或機構）數越多 |
| 兩概念距離近 → 技術相近 | 依共現支持數 N、Jaccard J 判斷；距離僅為排版 |
| 共現 → 技術依賴／整合／因果 | 共現表示同篇專利中共同出現 |
| 同社群 → 同類／同義 | 同社群表示在本樣本共現網路中結構連結較緊密 |
| 箭頭 → 先輩／演進／衍生 | 箭頭表示中位申請年較早指向較晚 |
| 機構連線 → 合作／聯盟 | 兩機構在各自專利中共同投入 N 個技術概念 |
| 模型權重 → 關係強度 | 模型判讀之信心指標，未經統計驗證，僅供回查 |

## 四、效度、限制與穩健性檢定的寫法

限制不是免責聲明，要寫成「已知邊界 + 已做／建議之檢定」。建議至少做前三項並把結果寫進論文，這是把探索型圖譜撐成可發表方法的最短路徑。

1. **人工校驗（最重要）**：由兩位以上領域研究者對隨機抽出之 n 篇專利（建議 ≥30 篇或 ≥10% 樣本）逐筆檢核概念相關性、概念邊界、關係方向與來源證據，報告一致性統計量（如 Cohen's κ）與錯誤類型分佈。**沒有這一項，圖譜的所有結論都停在「候選」層級。**
2. **模型依賴性檢定**：以另一模型或另一版 prompt 重跑同一樣本，報告概念集合之重疊率（Jaccard）與主要社群之穩定性。
3. **門檻與參數敏感度**：報告共現門檻（如 support ≥ 1/2/3）與 Louvain `resolution`（如 0.8/1.0/1.2）變動下，社群數與主要群聚組成之變化；並比較 Jaccard 與 NPMI 兩種邊權重下的排序差異。
4. **抽樣偏誤**：明寫「取前 N 筆、非隨機」，並以年份分佈、申請人分佈與原始排序之關聯性檢查是否存在系統性偏誤。
5. **同義詞邊界**：說明同義詞表之編輯會改變後續合併結果，並揭露表中條目數與版本；報告近似詞未合併之已知案例。
6. **樣本規模效應**：`support` 隨樣本增大而增大，跨資料集比較時須同時報告樣本數並以 Jaccard／NPMI 等正規化指標為主。
7. **機構層限制**：共享概念數以字面合併後之概念計數；共享連帶為統計共現，不代表實際合作或契約；機構類型為名稱規則判定，可能誤判；未連到任何邊之機構不出現於圖上（**這是視覺上的存活者偏誤，須在圖說註明**）。
8. **舊資料界線**：若論文使用系統重建之舊格式資料，須揭露方法標記（`cooccurrence_data: reconstructed` / `unavailable`、`semantic_provenance: partial`）；正式分析建議一律使用新版重新分析之資料。

## 六、審稿人最可能追問的五個問題與預備回應

1. **「LLM 抽出來的概念憑什麼算資料？」** → 用 3.2 的完整生成條件揭露 + 第四節第 1 項的人工校驗一致性數據回應。只講「用了 GPT／Claude」不足以構成方法。
2. **「換個模型結果就變了吧？」** → 承認模型依賴性，並出示第四節第 2 項的重疊率與社群穩定性檢定。這題不能靠辯解，只能靠數據。
3. **「Louvain 的社群是不是你調參調出來的？」** → 說明固定 `resolution = 1`、`randomWalk = false`（可重現）、社群僅用共現邊，並附 resolution 敏感度分析。
4. **「共現能推論什麼？」** → 明確界定共現為同篇出現之統計關聯，不推因果；需要因果或依賴時改以引用鏈與專家判讀。
5. **「圖上這兩個點靠得很近，代表什麼？」** → 距離僅為排版；比較請看 support 與 Jaccard。此句建議固定寫在每張圖的圖說。
