## 一、章節定位與組織

本章的核心問題是：如何將專利文本轉換為可追溯的技術概念與關係，再以網路方法描繪技術組合及其社群結構。建議沿用既有五節，但將「系統架構」寫成分析架構，減少軟體服務分層與介面功能的篇幅。

## 四、撰寫前必須補齊的研究資訊

- 專利資料庫、檢索式、檢索日、技術領域、年份與地理範圍。
- 檢索筆數、去重及排除規則、實際分析筆數、具有有效抽取結果的筆數。
- 實際分析是否只取前 N 筆；若是，說明非隨機取樣與排序造成的偏誤。系統支援前 N 筆選項不能代替實際樣本說明。
- 實際採用的模型、提示版本、生成參數、同義詞版本與分析紀錄。
- 主分析採專利篇數或申請人／機構家數。現行程式中的「家」是機構家數（`applicant`），不是專利家族（patent family）。若另需家族去重，必須取得家族識別資料並另行說明，不能直接把既有選項當家族分析。
- 社群辨識使用的語料範圍、權重、門檻與解析度；是否重新分群。
- 人工標註或專家檢核的設計與結果。若未做，明示候選圖譜的性質，不能宣稱抽取已獲驗證。

上述缺口補齊前，可撰寫方法框架，但不宜把框架當成可直接投稿的完整方法章。

## 五、現有大綱應先校正的內容

1. **「專利家族」改為「申請人／機構」**：`lib/concept-metrics.ts` 的兩種計數單位是 patent 與 applicant。機構單位先把同一機構各篇專利的概念取聯集，所以兩概念不必出現在同一篇專利，就可能算該機構共同涵蓋。這和專利內共現回答不同問題。
2. **「每篇 5–10 個概念」是提示要求**：`lib/llm/extractor.ts` 要求金融科技相關、避免空泛詞、盡量使用標準短詞，並要求關係端點來自抽取清單；不能因此聲稱每筆輸出都已通過數量、領域或語意品質驗證。輸出解析檢查與人工正確性評估須分開。
3. **語意權重與共現權重分開**：LLM 的 1–5 權重及 EXTRACTED／INFERRED／AMBIGUOUS 是模型產出的候選判讀。共現次數、Jaccard、NPMI 與 association strength 則由資料計算；模型權重不能替代統計權重，三級分類也不是校準過的正確機率。
4. **分群權重以目前程式為準**：`lib/louvain.ts` 的預設是 association strength、resolution = 1、randomWalk = false，且會回報社群連通分量數。舊文件記載 support 的地方不能照抄；檢查連通性不等於已保證所有群集連通。重現性須限於相同輸入與設定，也不能延伸為 LLM 抽取每次完全一致。
5. **同義詞是明確詞表映射**：主文須說明詞表如何建立及什麼詞允許合併；近義、相關與上下位概念不應自動視為同義。不能把系統的字串與詞表合併寫成已執行 embedding 聚類或 LLM 全自動消歧。
6. **association strength 的分母需明確**：目前程式以各節點相連共現邊的支持度總和計算，不能把分母寫成概念出現的專利篇數。Jaccard 與 NPMI 使用的邊際次數則另依專利或機構單位計算。正式公式應逐符號對照本次分析紀錄與實作。

## 七、3.3 與 3.4 的段落寫法示範

以下是依現行系統設計撰寫的工作草稿，尚須填入實際分析紀錄並與研究語料核對。

### 3.3 的開頭與方法重點

本研究以大型語言模型輔助辨識專利文本中的金融科技概念，將概念界定為能描述金融應用、技術功能或處理機制的具體術語。抽取時提供專利標題、摘要與申請人資訊，以摘要作為主要內容依據，並透過提示限制概念的領域範圍與表達粒度。提示要求每篇專利辨識五至十個概念，排除「系統」「方法」等缺乏區辨力的泛稱；通用技術詞彙則須具有可辨識的金融應用脈絡。此數量是生成指引，實際概念數仍須依輸出結果統計，而非預先固定。

除概念清單外，模型亦產生概念間的候選語意關係，並提供關係類型、判讀理由、相對權重與證據分類。證據分類區分摘要明確陳述、依脈絡推論及證據較弱三種情況，以保留不同判讀的差異。這些分類是模型輸出的輔助資訊，不代表經人工校驗的正確率。解析失敗的批次最多嘗試三次，仍無有效結果時保留來源專利並將抽取結果留空；其筆數及後續分析處理須另行揭露。所用模型、提示版本與生成條件應隨實際分析紀錄報告。

### 3.4 的開頭與方法重點

為避免同一技術因名稱差異而被拆分為多個節點，本研究在建圖前先整理抽取詞彙，再依明確的同義詞對應表映射至標準概念標籤。正規化旨在處理同一概念的不同表達，不把相關技術、上下位概念或同一社群內的詞彙視為等價。每次分析保留所使用的詞表版本與專利—概念對應，使概念合併及其對網路結構的影響能夠回溯。

圖譜以申請人、專利與技術概念為三類節點。申請人與專利之間的關係來自專利書目資訊，專利與概念之間的關係來自正規化後的抽取結果；LLM 判讀的候選語意關係另與資料計算的概念共現關係區分。概念網路由專利—概念對應投影而得，以同一分析單位內共同涵蓋兩概念作為建邊依據。採專利單位時，共現表示兩概念出現在同篇專利；採機構單位時，則表示同一機構的專利組合涵蓋兩概念。兩種表示分別反映專利內技術組合與機構技術組合，不能混用或解讀為技術因果關係。
