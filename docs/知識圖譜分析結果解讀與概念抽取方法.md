# 專利知識圖譜分析結果解讀與概念抽取方法

**文件版本**：v2.0  
**對應系統**：GraphData schema v2  
**更新日期**：2026-07-20

## 一、這套圖譜現在如何閱讀

系統將同一批專利資料呈現成兩張用途不同、但可以互相查證的圖：

1. **技術概念網路**：回答「哪些技術概念經常在同一篇專利中出現？」適合做技術群聚、核心概念與跨群連結探索。
2. **專利脈絡圖**：回答「這個概念來自哪篇專利、由哪個申請人提出？」適合追溯資料來源與查看年份脈絡。

這樣拆分的原因是：申請人、專利與概念的結構關係，和概念之間的統計關聯，不應混在同一張圖中用同一種線寬或距離解讀。兩張圖共用同一份資料，但研究問題不同。

## 二、技術概念網路代表什麼

### 2.1 節點

每個節點是一個由大型語言模型從專利摘要抽出的金融科技概念，例如「行動支付」「反洗錢」或「智能理財」。相同文字會合併為同一節點。

概念節點大小代表該概念出現於多少篇**不同專利**，不是摘要內的字詞出現次數，也不是引用數、品質或因果影響力。令某概念涵蓋的不同專利篇數為 `frequency`，顯示大小為：

```text
concept_size = clamp(10 + 6 × √frequency, 10, 52)
```

平方根縮放用來避免高頻概念過度放大。`clamp` 表示顯示尺寸最低為 10、最高為 52。示例：

| 涵蓋專利篇數 | 顯示大小 |
| ---: | ---: |
| 1 | 16 |
| 4 | 22 |
| 9 | 28 |
| 49 | 52（達上限） |

因此，正確表述是：「節點越大，代表此概念在本研究樣本中涵蓋的不同專利越多。」不能直接寫成「越大越重要」。

### 2.2 共現實線

概念 A 與概念 B 若在同一篇專利的概念清單中同時出現，兩者形成一條無向共現邊。系統以不同專利 ID 去重後計算：

```text
support(A,B) = 同時包含 A 與 B 的不同專利篇數
```

實線越粗，代表 `support` 越高。使用者可設定最低支持門檻；例如門檻為 3 時，只顯示至少有 3 篇不同專利共同支持的概念配對。此門檻只影響畫面顯示，不改寫原始圖譜資料。

點擊共現邊可查看：

- 共同專利支持篇數 `support_count`；
- Jaccard 相似度；
- 支持該共現的專利 ID。

Jaccard 的計算方式為：

```text
Jaccard(A,B) = |P(A) ∩ P(B)| / |P(A) ∪ P(B)|
```

其中 `P(A)` 是包含概念 A 的不同專利集合。Jaccard 介於 0 與 1，越高表示兩概念的專利集合重疊比例越高。它是共現集合的相似度，不是語意相似度，也不證明因果關係。

### 2.3 LLM 語意虛線

紫色虛線是大型語言模型根據單篇專利摘要判讀的具名關係，例如「應用於」「支援」或「提升」。此圖層預設關閉，開啟後用於補充解釋共現，而不是取代共現證據。

多篇專利產生完全相同的 `(source, target, relation)` 時，系統會聚合為一條語意邊並保存逐篇證據，包括來源專利、模型權重、理由與信心分類。模型權重可作為回查線索，但：

- 不決定實線粗細；
- 不參與 Louvain 社群偵測；
- 不改變節點間的彈簧長度；
- 不應當成經統計驗證的關係強度。

若模型產生的關係端點不在同一篇專利的概念清單內，程式會捨棄該關係，避免憑空新增概念節點。

### 2.4 顏色與社群

概念顏色代表 Louvain 社群。社群偵測只使用概念共現實線，邊權重為 `support_count`；LLM 語意虛線不參與計算。系統目前固定使用：

- 演算法：Louvain；
- resolution：1；
- randomWalk：false；
- 社群名稱：該社群中度數最高的概念；
- 沒有共現邊的概念：形成可重現的單點社群。

社群表示在目前樣本與建圖規則下「內部共現較緊密」的概念集合，不表示群內概念彼此同義，也不是唯一正確的技術分類。

## 三、專利脈絡圖代表什麼

專利脈絡圖保留三層來源結構：

```text
[申請人] ──申請了──> [專利] ──包含──> [技術概念]
```

| 元素 | 意義 | 資料來源 |
| --- | --- | --- |
| 申請人節點 | 專利申請機構 | Excel 申請人欄位 |
| 專利節點 | 一筆專利文件 | Excel 名稱、摘要、日期、申請號 |
| 概念節點 | 該專利被抽出的金融科技概念 | LLM 摘要抽取結果 |
| `申請了` | 申請人與專利的資料關係 | Excel |
| `包含` | 專利與抽取概念的來源關係 | LLM 關鍵詞清單 |

### 3.1 節點大小

申請人大小代表其連接的不同專利篇數：

```text
applicant_size = clamp(18 + 5 × √patent_count, 18, 52)
```

概念大小仍使用不同專利涵蓋篇數與前述概念公式。專利節點固定為 18，因此專利點大小不表示價值、品質、引用數或重要性。

### 3.2 年份篩選

年份篩選只作用於專利脈絡圖。篩選後系統會依可見專利重新計算：

- 申請人的專利篇數與點大小；
- 概念的涵蓋篇數、來源專利與點大小；
- 畫面上的申請人、專利、概念與社群數量。

沒有連到所選年份專利的節點會被移除。無日期專利只在完整年份範圍中納入。這可避免畫面已篩選年份，節點大小卻仍沿用全樣本數值的矛盾。

### 3.3 結構線

`申請了` 與 `包含` 使用固定線寬。它們表示資料中的存在關係，不代表關係強弱。專利脈絡圖不顯示概念共現或 LLM 語意邊，以維持來源追溯的清楚性。

## 四、點與點的距離代表什麼

### 4.1 唯一安全的解讀

> 圖中座標僅供排版；兩點的畫面距離不是定量研究指標。

系統使用力導向演算法避免節點重疊並讓連線結構較容易閱讀。位置會同時受到全圖節點數、邊數、排斥力、彈簧、初始座標與穩定化過程影響。因此，即使兩點靠近，也不能單獨推論它們的技術相似度或關係強度。

畫面距離不能解讀為：

- 語意相似度分數；
- 共現機率；
- 因果強度或技術依賴程度；
- 企業競爭程度；
- 統計顯著性；
- 時間先後。

需要比較兩概念時，應查看共現 `support`、Jaccard、來源專利與語意關係證據，而不是量測像素距離。介面圖例、論文模式與 HTML 匯出頁均固定顯示此限制；離線 HTML 亦內建雙模式切換，兩種模式都使用匯出時經同一套規則計算的視圖資料。

## 五、概念如何從專利中抽出

### 5.1 處理流程

```text
Excel 專利資料
→ 依設定取前 N 筆
→ 分批、有限並行送入選定 LLM
→ 取得繁體中文摘要、keywords 與 relations
→ 清理並以專利內去重的 keywords 建立概念成員關係
→ 計算跨專利 frequency、共現 support 與 Jaccard
→ 以共現網路執行 Louvain
→ 建立技術概念網路與專利脈絡圖
```

### 5.2 模型輸入

每筆送入模型的欄位是：

- 專利名稱；
- 專利摘要；
- 申請人。

申請日、申請號與搜尋關鍵字不直接參與概念抽取。提示詞以摘要為主要證據，要求模型輸出純 JSON。

### 5.3 提示詞規則

目前提示詞版本為 `fintech-concepts-v2`，要求模型：

1. 將摘要翻譯或潤飾為繁體中文；
2. 每篇抽取 5 至 10 個金融科技相關的具體概念；
3. 排除「系統」「方法」「裝置」等空泛詞；
4. 通用技術詞必須帶有金融場景；
5. 優先採用 2 至 6 字的業界標準詞彙；
6. 關係端點必須來自同篇 `keywords`；
7. 關係需回傳名稱、1 至 5 權重、理由，以及 `EXTRACTED`、`INFERRED` 或 `AMBIGUOUS` 信心分類。

程式會記錄 prompt 版本、模型提供商與模型 ID，讓後續結果能交代生成條件。

### 5.4 程式清理與聚合

模型回傳後，程式對每篇專利的 `keywords`：

1. 去除字串前後空白；
2. 移除空字串；
3. 以完全相同字串去重；
4. 以穩定順序建立概念與概念配對。

目前沒有同義詞表、詞形正規化、本體對齊或人工合併，所以「行動支付」與「行動支付技術」仍可能成為兩個節點。這是論文中必須揭露的概念邊界限制。

LLM 整批回覆若無法解析為正確筆數的 JSON 陣列，最多嘗試三次；全部失敗時，該批專利仍保留，但概念與關係為空。

## 六、這樣符合知識圖譜嗎

本系統具備知識圖譜的基本結構：

- 具有明確類型的實體：申請人、專利、技術概念；
- 具有具名關係：申請了、包含，以及候選語意關係；
- 節點與邊具有年份、頻率、支持數、來源專利、理由等屬性；
- 可由關係追溯到資料來源；
- 可進行社群與網路結構分析。

因此可稱為：

> LLM 輔助建構的專利異質屬性知識圖譜

不過，技術概念與語意關係由模型抽取，尚未經完整領域本體、專家逐筆校驗或外部知識庫對齊。論文中較穩健的說法是「研究探索型知識圖譜」或「候選知識圖譜」，不要宣稱為已完全驗證的權威知識庫。

其中，專利脈絡圖承擔知識圖譜的來源追溯功能；技術概念網路則是從專利—概念成員關係投影出的共現分析網路。兩者在系統中並存，但研究解釋應分開。

## 七、舊資料的相容與證據界線

新版資料使用 `schema_version: 2` 並保存方法資訊。載入舊版 JSON 時，系統會盡可能從既有的「專利 → 概念」邊重建概念頻率、共現支持數、Jaccard 與社群。

- 能重建時，方法標記為 `cooccurrence_data: reconstructed`；
- 缺少專利—概念成員關係時，標記為 `unavailable`，不虛構共現統計；
- 舊版 LLM 邊若只有單一 `source_patent`，標記為 `semantic_provenance: partial`；
- 舊版沒有保存的理由、信心或完整支持篇數維持缺值，不以預設值冒充證據。

介面會顯示能力警告。因此，論文正式分析應優先使用新版重新分析產生的資料；舊資料適合回顧與探索，但其證據完整性必須另行說明。

## 八、論文可直接使用的方法描述

> 本研究以專利文件為分析單位，將申請人、專利與大型語言模型自摘要抽取之金融科技概念建構為異質屬性知識圖譜。為區分資料來源追溯與技術結構分析，系統分別呈現專利脈絡圖及技術概念網路。概念頻率定義為包含該概念之不同專利篇數，概念節點大小採平方根縮放；兩概念之實證連結則以共同出現於不同專利的篇數作為支持數，並另計 Jaccard 相似度。技術社群使用以共同專利支持數加權之 Louvain 演算法辨識。大型語言模型判讀之具名語意關係以獨立虛線圖層呈現，不納入社群計算或版面距離設定。力導向圖之座標僅用於視覺排版，不作為語意距離或因果強度指標。所有候選概念與語意關係仍應透過來源專利回查及人工抽樣驗證。

## 九、結果段落可直接使用的解讀句型

- 「概念 A 的節點較大，表示其涵蓋的不同專利篇數較多，反映其在本研究樣本中的普及廣度。」
- 「概念 A 與 B 的共現支持數為 N，表示兩者共同出現於 N 篇不同專利；Jaccard 值為 J，表示兩者專利集合的重疊比例。」
- 「概念 A 與 B 被分入同一 Louvain 社群，表示在本樣本的專利共現網路中具有較密切的結構連結；此結果不等同於兩概念同義。」
- 「紫色虛線為模型依摘要提出的候選語意關係，需搭配線上所列來源專利與理由回查。」
- 「圖中節點位置由力導向排版產生，因此不比較兩點的像素距離。」

## 十、研究限制與建議驗證

1. LLM 抽取具有模型與提示詞依賴性；更換模型或重新分析可能改變結果。
2. 目前只以完全相同文字合併概念，同義詞可能被拆分，同名異義詞也可能被合併。
3. 共現表示同篇專利共同出現，不代表因果、技術依賴或實際整合。
4. `support` 受樣本大小影響，跨資料集比較時應同時報告樣本數並參考 Jaccard。
5. Louvain 是資料驅動分群，不是唯一分類；研究可用不同門檻或演算法做穩健性分析。
6. 目前「抽樣」為取輸入資料前 N 筆，不是隨機抽樣；原始排序可能造成樣本偏差。
7. 建議由兩位以上領域研究者抽樣檢核概念相關性、概念邊界、關係方向與來源證據，並報告一致性。
8. 論文附錄應保存資料範圍、模型提供商、模型 ID、prompt 版本、分析時間、共現門檻與系統版本。
