# 專利知識圖譜分析結果解讀與概念抽取方法

- **文件版本**：v2.3
- **對應系統**：GraphData schema v4
- **更新日期**：2026-08-12

## 一、這套圖譜現在如何閱讀

系統將同一批專利資料呈現成三張用途不同、但可以互相查證的圖：

1. **技術概念網路**：回答「哪些技術概念經常在同一篇專利中出現？」適合做技術群聚、核心概念與跨群連結探索。
2. **專利脈絡圖**：回答「這個概念來自哪篇專利、由哪個申請人提出？」適合追溯資料來源與查看年份脈絡。
3. **機構網路**：回答「哪些機構共同投入哪些技術概念？」以機構為節點、共享概念為連帶，適合研究機構之間的技術連帶與版圖。

這樣拆分的原因是：申請人、專利與概念的結構關係，和概念之間的統計關聯，不應混在同一張圖中用同一種線寬或距離解讀。三張圖共用同一份資料，但研究問題不同。

## 二、技術概念網路代表什麼

### 2.1 節點

每個節點是一個由大型語言模型從專利摘要抽出的金融科技概念，例如「行動支付」「反洗錢」或「智能理財」。相同文字會合併為同一節點；列入同義詞表的異名（如「人工智慧」與「AI」）也會合併為同一節點。

概念節點大小代表該概念出現於多少篇**不同專利**，不是摘要內的字詞出現次數，也不是引用數、品質或因果影響力。令某概念涵蓋的不同專利篇數為 `frequency`，顯示大小為：

```text
concept_size = clamp(10 + 10 × √frequency, 10, 72)  // 2026-08-09：斜率 6→10、上限 52→72
```

平方根縮放用來避免高頻概念過度放大。`clamp` 表示顯示尺寸最低為 10、最高為 72。示例：

| 涵蓋專利篇數 |     顯示大小 |
| -----------: | -----------: |
|            1 |           20 |
|            4 |           30 |
|            9 |           40 |
|           39 | 72（達上限） |

節點大小隨分析單位切換：「篇」單位代表涵蓋的不同專利篇數；切至「家」單位則代表涵蓋的不同申請機構家數。

因此，正確表述是：「節點越大，代表此概念在本研究樣本中涵蓋的不同專利（或機構）越多。」不能直接寫成「越大越重要」。

### 2.2 共現實線

概念 A 與概念 B 若在同一篇專利的概念清單中同時出現，兩者形成一條無向共現邊。系統以不同專利 ID 去重後計算：

```text
support(A,B) = 同時包含 A 與 B 的不同專利篇數
```

實線越粗，代表 `support` 越高。使用者可設定最低支持門檻；例如門檻為 3 時，只顯示至少有 3 篇不同專利共同支持的概念配對。此門檻只影響畫面顯示，不改寫原始圖譜資料。

點擊共現邊可查看：

- 共同專利支持篇數 `support_count`；
- Jaccard 相似度；
- 支持該共現的專利 ID。

Jaccard 的計算方式為：

```text
Jaccard(A,B) = |P(A) ∩ P(B)| / |P(A) ∪ P(B)|
```

其中 `P(A)` 是包含概念 A 的不同專利集合。Jaccard 介於 0 與 1，越高表示兩概念的專利集合重疊比例越高。它是共現集合的相似度，不是語意相似度，也不證明因果關係。

### 2.3 LLM 語意虛線

紫色虛線是大型語言模型根據單篇專利摘要判讀的具名關係，例如「應用於」「支援」或「提升」。此圖層預設關閉，開啟後用於補充解釋共現，而不是取代共現證據。

多篇專利產生完全相同的 `(source, target, relation)` 時，系統會聚合為一條語意邊並保存逐篇證據，包括來源專利、模型權重、理由與信心分類。模型權重可作為回查線索，但：

- 不決定實線粗細；
- 不參與 Louvain 社群偵測；
- 不改變節點間的彈簧長度；
- 不應當成經統計驗證的關係強度。

若模型產生的關係端點不在同一篇專利的概念清單內，程式會捨棄該關係，避免憑空新增概念節點。

### 2.4 顏色與社群

概念顏色代表 Louvain 社群。社群偵測只使用概念共現實線，邊權重為 `support_count`；LLM 語意虛線不參與計算。系統目前固定使用：

- 演算法：Louvain；
- resolution：1；
- randomWalk：false；
- 社群名稱：該社群中度數最高的概念；
- 沒有共現邊的概念：形成可重現的單點社群。

社群表示在目前樣本與建圖規則下「內部共現較緊密」的概念集合，不表示群內概念彼此同義，也不是唯一正確的技術分類。

## 三、專利脈絡圖代表什麼

專利脈絡圖保留三層來源結構：

```text
[申請人] ──申請了──> [專利] ──包含──> [技術概念]
```

| 元素       | 意義                       | 資料來源                       |
| ---------- | -------------------------- | ------------------------------ |
| 申請人節點 | 專利申請機構               | Excel 申請人欄位               |
| 專利節點   | 一筆專利文件               | Excel 名稱、摘要、日期、申請號 |
| 概念節點   | 該專利被抽出的金融科技概念 | LLM 摘要抽取結果               |
| `申請了`   | 申請人與專利的資料關係     | Excel                          |
| `包含`     | 專利與抽取概念的來源關係   | LLM 關鍵詞清單                 |

### 3.1 節點大小

申請人大小代表其連接的不同專利篇數：

```text
applicant_size = clamp(18 + 5 × √patent_count, 18, 52)
```

概念大小仍使用不同專利涵蓋篇數與前述概念公式。專利節點固定為 18，因此專利點大小不表示價值、品質、引用數或重要性。

### 3.2 年份篩選

年份篩選同時作用於技術概念網路與專利脈絡圖（兩模式皆提供雙把手年份滑桿）。

- 概念模式：依選定的專利子集重新推導概念節點、關係與各項指標——涵蓋篇數／家數、首次出現年、四分位與中位年等時間元資料，以及共現 support、Jaccard 與 NPMI；社群分區沿用既有演算法結果，門檻只過濾顯示。
- 專利脈絡圖：依可見專利重新計算申請人的專利篇數與點大小、概念的涵蓋篇數與點大小，以及畫面上的申請人、專利、概念與社群數量；沒有連到所選年份專利的節點會被移除。

無日期專利只在完整年份範圍中納入。這可避免畫面已篩選年份，節點大小卻仍沿用全樣本數值的矛盾。

### 3.3 結構線

`申請了` 與 `包含` 使用固定線寬。它們表示資料中的存在關係，不代表關係強弱。專利脈絡圖不顯示概念共現或 LLM 語意邊，以維持來源追溯的清楚性。

## 四、機構網路代表什麼

機構網路以「機構」為節點，回答「哪些機構共同投入哪些技術？」。它直接服務「某銀行＋某大學一起做哪些技術」這類研究問題，由既有的結構關係在視圖層重建，不重新呼叫 LLM。

### 4.1 節點與大小

每個節點是一間申請機構（申請人）。系統先由 `申請了` 邊重建每家機構的專利集合，再經 `包含` 邊收集該機構所有專利涵蓋的概念聯集；涵蓋概念數為 0 的機構不顯示。節點大小代表該機構涵蓋的**不同技術概念數**：

```text
institution_size = min(52, 18 + 5 × √(涵蓋概念數))
```

機構節點越大，表示其涉足的技術概念越多；這是概念廣度，不是專利篇數、市佔或影響力。

### 4.2 邊：共享概念連帶

若兩家機構的共同概念數 ≥ k，兩者之間形成一條無向邊：

```text
support(A,B) = 兩機構共同涵蓋的技術概念數
```

k 由介面的「最低共享概念數」滑桿控制（預設 1），只影響顯示，不更動底層資料；調高門檻可聚焦強連帶。線寬隨共享概念數增加而變粗（`min(8, 1 + 1.4 × √support)`）。點擊邊可查看共享概念的完整清單。

### 4.3 顏色：機構類型

節點顏色代表規則式判定的機構類型：銀行、金控、保險、大學、證券投承、支付金流、科技、學研、個人、其他。「大學」優先於一般學研拆分，以便直接觀察「銀行 × 大學」的合作故事。分類依機構名稱關鍵字即時判定（規則見 `lib/applicant-classify.ts`），是粗略的產業標籤，不是官方產業分類。

### 4.4 邊界與閱讀提醒

- 共享概念數以「字面合併後的概念」計數，受同義詞表與 LLM 抽取品質影響。
- 共享連帶表示「兩機構都在自己的專利中投入這些技術」，是統計共現，不代表實際合作、合約或競爭關係。
- 本圖不畫概念節點；想知道共享概念之間的技術結構，請回技術概念網路。
- 只顯示至少連到一條邊的機構；完全沒有共享連帶的機構不會出現在圖上。

## 五、點與點的距離代表什麼

### 5.1 唯一安全的解讀

> 圖中座標僅供排版；兩點的畫面距離不是定量研究指標。

系統使用力導向演算法避免節點重疊並讓連線結構較容易閱讀。位置會同時受到全圖節點數、邊數、排斥力、彈簧、初始座標與穩定化過程影響。因此，即使兩點靠近，也不能單獨推論它們的技術相似度或關係強度。機構網路亦同——機構邊不參與力導向模擬，座標由連線結構的啟發式初始位置決定，兩機構靠近不表示合作強度。

畫面距離不能解讀為：

- 語意相似度分數；
- 共現機率；
- 因果強度或技術依賴程度；
- 企業競爭程度；
- 統計顯著性；
- 時間先後。

需要比較兩概念時，應查看共現 `support`、Jaccard、來源專利與語意關係證據，而不是量測像素距離。介面圖例、論文模式與 HTML 匯出頁均固定顯示此限制；離線 HTML 亦內建多模式切換，各模式都使用匯出時經同一套規則計算的視圖資料。

## 六、概念如何從專利中抽出

### 6.1 處理流程

```text
Excel 專利資料
→ 依設定取前 N 筆
→ 分批、有限並行送入選定 LLM
→ 取得繁體中文摘要、keywords 與 relations
→ 清理並以專利內去重的 keywords 建立概念成員關係
→ 計算跨專利 frequency、共現 support 與 Jaccard
→ 以共現網路執行 Louvain
→ 建立技術概念網路、專利脈絡圖與機構網路
```

### 6.2 模型輸入

每筆送入模型的欄位是：

- 專利名稱；
- 專利摘要；
- 申請人。

申請日、申請號與搜尋關鍵字不直接參與概念抽取。提示詞以摘要為主要證據，要求模型輸出純 JSON。

### 6.3 提示詞規則

目前提示詞版本為 `fintech-concepts-v2`，要求模型：

1. 將摘要翻譯或潤飾為繁體中文；
2. 每篇抽取 5 至 10 個金融科技相關的具體概念；
3. 排除「系統」「方法」「裝置」等空泛詞；
4. 通用技術詞必須帶有金融場景；
5. 優先採用 2 至 6 字的業界標準詞彙；
6. 關係端點必須來自同篇 `keywords`；
7. 關係需回傳名稱、1 至 5 權重、理由，以及 `EXTRACTED`、`INFERRED` 或 `AMBIGUOUS` 信心分類。

程式會記錄 prompt 版本、模型提供商與模型 ID，讓後續結果能交代生成條件。

### 6.4 程式清理與聚合

模型回傳後，程式對每篇專利的 `keywords`：

1. 去除字串前後空白；
2. 移除空字串；
3. 以完全相同字串去重；
4. 以穩定順序建立概念與概念配對。

概念合併發生在共現計算的輸入層：完全相同文字必然合併；列入同義詞表的異名（如「人工智慧」與「AI」）在輸入層先正規化為同一代表詞再合併，因此共現邊的支持數是合併後的聯集。未列入同義詞表的近似詞（如「行動支付」與「行動支付技術」）仍會成為兩個節點。這是論文中必須揭露的概念邊界限制。

LLM 整批回覆若無法解析為正確筆數的 JSON 陣列，最多嘗試三次；全部失敗時，該批專利仍保留，但概念與關係為空。

## 七、這樣符合知識圖譜嗎

本系統具備知識圖譜的基本結構：

- 具有明確類型的實體：申請人、專利、技術概念；
- 具有具名關係：申請了、包含，以及候選語意關係；
- 節點與邊具有年份、頻率、支持數、來源專利、理由等屬性；
- 可由關係追溯到資料來源；
- 可進行社群與網路結構分析。

因此可稱為：

> LLM 輔助建構的專利異質屬性知識圖譜

不過，技術概念與語意關係由模型抽取，尚未經完整領域本體、專家逐筆校驗或外部知識庫對齊。論文中較穩健的說法是「研究探索型知識圖譜」或「候選知識圖譜」，不要宣稱為已完全驗證的權威知識庫。

其中，專利脈絡圖承擔知識圖譜的來源追溯功能；技術概念網路是從專利—概念成員關係投影出的共現分析網路；機構網路則是機構層級的技術連帶視角。三者在系統中並存，但研究解釋應分開。

## 八、舊資料的相容與證據界線

現行資料使用 `schema_version: 4`（v2、v3 亦相容載入）並保存方法資訊。載入舊版 JSON 時，系統會盡可能從既有的「專利 → 概念」邊重建概念頻率、共現支持數、Jaccard 與社群。

- 能重建時，方法標記為 `cooccurrence_data: reconstructed`；
- 缺少專利—概念成員關係時，標記為 `unavailable`，不虛構共現統計；
- 舊版 LLM 邊若只有單一 `source_patent`，標記為 `semantic_provenance: partial`；
- 舊版沒有保存的理由、信心或完整支持篇數維持缺值，不以預設值冒充證據。

專利脈絡圖與機構網路都只依賴結構邊（`申請了`／`包含`）在視圖層重建，因此舊格式只要有結構邊即可正常顯示；缺少「家」單位統計的舊分析，在概念視圖切至「家」單位時會顯示重建提示。

介面會顯示能力警告。因此，論文正式分析應優先使用新版重新分析產生的資料；舊資料適合回顧與探索，但其證據完整性必須另行說明。

## 九、論文可直接使用的方法描述

> 本研究以專利文件為分析單位，將申請人、專利與大型語言模型自摘要抽取之金融科技概念建構為異質屬性知識圖譜。為區分資料來源追溯與技術結構分析，系統分別呈現專利脈絡圖及技術概念網路。概念頻率定義為包含該概念之不同專利篇數，概念節點大小採平方根縮放；兩概念之實證連結則以共同出現於不同專利的篇數作為支持數，並另計 Jaccard 相似度。技術社群使用以共同專利支持數加權之 Louvain 演算法辨識。另以機構網路呈現機構間的技術連帶，節點為申請機構、其大小依涉足之技術概念數平方根縮放，兩機構之連結強度為其共同涵蓋之概念數，機構類型以名稱規則分類。大型語言模型判讀之具名語意關係以獨立虛線圖層呈現，不納入社群計算或版面距離設定。力導向圖之座標僅用於視覺排版，不作為語意距離或因果強度指標。所有候選概念與語意關係仍應透過來源專利回查及人工抽樣驗證。

## 十、結果段落可直接使用的解讀句型

- 「概念 A 的節點較大，表示其涵蓋的不同專利篇數較多，反映其在本研究樣本中的普及廣度。」
- 「概念 A 與 B 的共現支持數為 N，表示兩者共同出現於 N 篇不同專利；Jaccard 值為 J，表示兩者專利集合的重疊比例。」
- 「概念 A 與 B 被分入同一 Louvain 社群，表示在本樣本的專利共現網路中具有較密切的結構連結；此結果不等同於兩概念同義。」
- 「紫色虛線為模型依摘要提出的候選語意關係，需搭配線上所列來源專利與理由回查。」
- 「機構 A 與 B 之間的連帶表示兩者在其專利中共同投入了 N 個技術概念；點擊邊可查看共享概念清單。」
- 「機構節點較大，表示其涉足的不同技術概念較多，反映其技術版圖的廣度。」
- 「圖中節點位置由力導向排版產生，因此不比較兩點的像素距離。」

## 十一、研究限制與建議驗證

1. LLM 抽取具有模型與提示詞依賴性；更換模型或重新分析可能改變結果。
2. 目前只以完全相同文字合併概念，同義詞可能被拆分，同名異義詞也可能被合併；同義詞表的編輯會改變後續分析的合併結果。
3. 共現表示同篇專利共同出現，不代表因果、技術依賴或實際整合。
4. `support` 受樣本大小影響，跨資料集比較時應同時報告樣本數並參考 Jaccard。
5. Louvain 是資料驅動分群，不是唯一分類；研究可用不同門檻或演算法做穩健性分析。
6. 目前「抽樣」為取輸入資料前 N 筆，不是隨機抽樣；原始排序可能造成樣本偏差。
7. 建議由兩位以上領域研究者抽樣檢核概念相關性、概念邊界、關係方向與來源證據，並報告一致性。
8. 論文附錄應保存資料範圍、模型提供商、模型 ID、prompt 版本、分析時間、共現門檻與系統版本。
9. 機構網路的共享概念數以字面合併後的概念計數，同義詞表與抽取品質會直接影響共享數與連帶。
10. 機構類型為名稱關鍵字規則分類，非官方產業分類，可能誤判。
11. 機構間共享連帶是概念共現統計，不代表實際合作或契約關係；解讀與論文寫作時應以專利與公開資料回查。

## 十二、視覺屬性的數學公式：方向、上下位、距離與粗細

本章把技術概念網路上四種視覺屬性的產生規則寫成可檢查的公式，作為前文各節的補充。論文如需描述視覺映射，可直接引用本章公式並附上參數值。

### 12.1 方向（箭頭）怎麼來

箭頭只出現在三類邊上；共同出現實線本身是無向邊，沒有箭頭。

**語意邊（紫色虛線）**：方向由大型語言模型抽取時自行判斷，`source → target` 即箭頭方向，系統不改寫方向。關係名稱（如「包含」「應用於」「提升」）是自由文字，不進入公式；邊權重為各篇模型權重的平均值：

```text
weight = mean(各篇 weight)   // weight 為 1–5
```

**時間邊（共同出現邊帶方向時）**：以兩端概念的中位申請年排序決定方向（`lib/temporal.ts` 的 `orientPair`）：

```text
若 median(A) < median(B)：方向 A → B
若 median(A) > median(B)：方向 B → A
若相等或缺值：不設方向（畫為無向）
```

中位年為該概念涵蓋專利的申請年中位數；偶數筆取中間兩數平均。方向完全由兩個中位數決定，不參考標籤、ID 或雜湊值。

#### 為何是「時間先後」，不是「先輩關係」

這個規則作為**探索性的時間排序**是合理的：中位數較不易被少數極早或極晚的專利影響，且會隨目前選取的 IPC、來源檔與年份範圍，用同一批專利重新計算。它回答的是：「在目前樣本中，兩個已具有共現關係的概念，哪一個較早出現於其涵蓋專利？」

但箭頭不應稱為「先輩／祖先」或「技術演進、因果」關係。產生時間箭頭必須同時滿足：

1. 兩概念已由共同出現的專利形成概念關係；
2. 兩端在目前分析子集內都有可比較、且不相等的中位申請年；
3. 箭頭一律由較早的中位申請年指向較晚者。

若中位年相同或任一端缺少有效年份，系統不畫時間箭頭；專利引用資料也不會反轉方向，只用來標示它與時間排序是否一致。要主張真正的技術傳承、依賴或因果，仍須另以引用鏈、權利項／技術內容與領域專家判讀驗證。

**引用佐證邊（藍色）**：方向仍由中位年決定，專利引用只做佐證與衝突分類（`citationAdjudication`）：

```text
net = max(f, r) − min(f, r)          // f = 順向引用數, r = 反向引用數
ratio = max(f, r) / min(f, r)
支援判定：net ≥ 2 且 ratio ≥ 2
f > r  → aligned（藍色，標示「引用」）
f < r  → conflicting（紅色，標示「⚠」，與中位年排序方向衝突）
```

### 12.2 上下位（階層）

本系統**沒有**樹狀階層排版；圖中的垂直位置不是上下位，概念網路上的箭頭也不是技術分類的父子箭頭。應區分三種不同關係：

1. **候選方向性語意關係**：模型可產出 `source → target` 的關係字串。只有明確寫為「包含」「上位概念」等關係時，才可暫時視為候選上下位；「應用於」「支援」「提升」等方向性關係並不等於分類階層。所有此類關係都需回查來源專利，不能當作已驗證本體。
2. **結構二部邊**：`申請了`（申請人 → 專利）與 `包含`（專利 → 概念）是資料存在關係，固定線寬，不代表技術概念間的上下位或先後。
3. **IPC 分類樹**：這才是可由分類碼直接判定的父子階層。正規化 IPC 以代碼前綴投影為五級：L1=`G`、L2=`G06`、L3=`G06Q`、L4=`G06Q10`、L5=`G06Q10/10`；前一級是後一級的父層。IPC 樹只用於瀏覽、篩選與著色（`lib/ipc-filter.ts` 的 `ipcKeyAtLevel`／`ipcTreeOf`），不會產生或決定概念網路上的箭頭。

因此，描述 IPC 時可使用「父層／子層分類」；描述概念網路的箭頭時應使用「較早／較晚的時間排序」，不應混稱為「先輩／後輩」。

### 12.3 距離（節點間）

節點座標由 forceAtlas2 力導向模擬收斂產生（`components/GraphViewer.tsx` 的 `buildOptions`），不是每條邊有固定距離公式。三種力：

```text
斥力（每對節點）：   F_r = k × (deg_i + 1)(deg_j + 1) / d²
彈簧引力（每條邊）： F_s = c × (d − L)
向心力（朝圖中心）： F_c = γ × d
```

```text
參數（小圖／大圖 ≥120 節點）：
k（gravitationalConstant）= −150／−80
L（springLength）        = 250／150
c（springConstant）      = 0.04
γ（centralGravity）     = 0.003
damping = 0.5、avoidOverlap = 1
maxVelocity = 50、minVelocity = 0.75
穩定化迭代 = 200（大圖 130、超大圖 ≥350 為 80）
```

收斂後的座標只做視覺排版：**任何兩點的像素距離都不是定量研究指標**（見第五節），不能用來比較語意相似度、共現機率或因果強度。語意虛線與機構邊不參與模擬（`physics: false`），不影響版面。時間檢視另使用依中位年排序的座標（`computeTemporalLayout`）：X 由中位年等級決定，節點 ID 只在同一年的 Y 帶內微調。

### 12.4 粗細（線寬）

**共同出現實線**（`cooccurrenceWidth`，預設使用 Jaccard；`support` 本身不直接用於線寬）：

```text
Jaccard 模式：width = min(8, 1 + 7 × Jaccard)
NPMI 模式：   width = min(8, 1 + 7 × max(0, NPMI))
```

Jaccard 見第二節 2.2：`Jaccard(A,B) = |P(A) ∩ P(B)| / |P(A) ∪ P(B)|`。「篇／家」單位各自計算一份。

NPMI（正規化點間互資訊）以篇為單位：

```text
p_xy = support(A,B) / 總專利數，p_x = freq(A) / 總專利數，p_y = freq(B) / 總專利數
NPMI = (ln p_xy − ln p_x − ln p_y) / (−ln p_xy)
結果 clamp 至 [−1, 1]
```

特殊規則：`p_xy = 1`（兩概念永遠共同出現）時 NPMI 不定義，邊詳細顯示「—」且不參與線寬與排序——該況 PMI 為 0，記成量尺最大值會與語意相反。

**其他邊**：語意邊固定 1.5（虛線，粗細不隨模型權重變化）；機構邊 `min(8, 1 + 1.4 × √support)`（見 4.2）；引用邊固定 1.5。

**透明度**（共現邊依支持數淡出，`supportStrengthOpacity`，τ = 5 為視覺啟發值非信心值）：

```text
opacity = 0.30 + 0.70 × (1 − e^(−support/5))
```

**節點大小**：概念 `min(72, max(10, 10 + 10 × √frequency))`（見 2.1）；申請人 `min(52, max(18, 18 + 5 × √patent_count))`（見 3.1）；專利固定 18。

**不當線寬的指標**：association strength `= 2 × m × c_ij / (c_a × c_b)`（其中 `m = ½Σc_i`，`c_i` 為概念 i 的所有共現邊支持數總和）只做圖內排序與門檻，**不映射為線寬**（意圖決策 2），避免讓圖面讀起來像未經驗證的強度分數。

**對應程式位置**（維護用）：方向 `lib/temporal.ts`、`lib/graph-view.ts`；語意抽取 `lib/llm/extractor.ts`、聚合 `lib/concept-network.ts`；指標 `lib/concept-metrics.ts`；線寬與物理 `components/GraphViewer.tsx`、`lib/temporal.ts`。
